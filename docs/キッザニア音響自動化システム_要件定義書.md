# キッザニア館内音響自動化システム 要件定義書

作成日: 2026年7月25日
バージョン: v0.1(ドラフト)

---

## 1. プロジェクト概要

現在Windowsタスクスケジューラーで個別に実行している館内音楽・ステージ演出の
再生を、単一のPythonアプリケーションに統合する。朝に一度起動しておけば、
以降は無人でスケジュール通りに音楽が自動再生され、ステージショーはZV
(スタッフ)がボタン操作で手動トリガーできる状態を目指す。

## 2. 現状の課題

- タスクスケジューラーで個別に音楽ファイルを起動しているため、音源ごとの
  音量差を都度手動調整する必要がある
- 複数のプレイヤー/プロセスがバラバラに常駐し、管理が煩雑
- ステージ演出はPowerPointで動画・音楽を再生しており、同期が不安定になりやすい

## 3. 機能要件

### 3.1 自動音楽再生機能(スケジュール実行)

- 指定時刻に指定した音源ファイルを自動再生する(館内BGM等)
- 毎時1回、街時計ダンス用の音楽を自動再生する
  - 再生中は館内BGM(別端末・別システムで再生中)が自動的に小さくなる
    (ハード側のダッキング処理と推定。詳細は「7. 未確定事項」参照)
  - 再生終了後は特に操作せずとも館内BGMの音量が自動的に戻る想定
- スケジュールはcron形式で管理し、担当者が時刻・音源を編集できること
  (例: `APScheduler`によるジョブ管理)
- 音源ごとに個別の再生音量を設定・保持できること
  (旧タスクスケジューラー方式の課題を解消)

### 3.2 ステージショー手動再生機能

- ZV(スーパーバイザー以下スタッフ)がPythonシステムのGUI上の
  スタートボタンを押すと、対応する動画ファイル(ダンスショー/
  ファッションショー、音楽・映像入り)をフルスクリーンで再生する
- 現行PowerPointでの運用を廃止し、動画ファイル+専用プレイヤーに置き換える
  (音声・映像の同期問題を解消するため)
- 再生はPC→HDMI出力→音響映像システム→スクリーンの経路
- **前提条件**: 動画再生前に、音響映像スタッフが操作盤で入力を
  「イベント卓」に手動切替していること(本システムの制御範囲外。
  詳細は「6. 運用フロー」参照)

### 3.3 音量管理機能

- 音源(館内BGM/街時計/ステージ動画など)ごとに個別音量設定を保持
- GUIまたは設定ファイルで音量を調整・保存できること

### 3.4 映像出力機能

- 動画ファイルをフルスクリーンでHDMI出力できること
- 音声・映像のズレが生じないこと

## 4. 非機能要件

- ローカル音源ファイルのみで動作すること(オフライン動作可能。
  将来的にネット経由の音源配信を追加する余地は残す)
- 常駐プロセスは1つのみとし、朝1回の起動で以降は無人運用できること
- 再生失敗時(ファイル破損・出力デバイス切断等)にアプリ全体が
  停止しないこと、ログに記録されること
- 誰が触っても安全な最小限のGUI(誤操作防止)であること

## 5. システム構成(現時点の想定)

| 要素 | 想定技術 |
|---|---|
| スケジュール管理 | Python + APScheduler |
| 音声・動画再生 | python-vlc(VLCエンジン) |
| 手動トリガーGUI | Tkinter または PyQt |
| 音量管理 | アプリ内設定(JSON等)で音源ごとに保持 |
| 実行環境 | Windows常駐(会社PC、HDMI出力) |

## 6. 運用フロー(現状把握分)

1. 朝、担当者がPythonアプリを起動(以降は無人でスケジュール実行)
2. 通常時間帯: 館内BGMを別端末が再生中
3. 毎時: 本システムが街時計音楽を自動再生 → 館内BGM側が自動的に
   ダッキング → 再生終了後、館内BGM音量が自動的に復帰
4. ステージショー実施時:
   a. 音響映像スタッフが操作盤で「イベント卓」入力に手動切替
   b. ZVが本システムのスタートボタンを押す
   c. 動画がフルスクリーン再生(音声・映像同期)

## 7. 制約事項・外部依存

- 映像入力の切替(イベント卓)は音響映像スタッフの手動操作であり、
  本システムから自動制御はしない(現状、切替機材がAPI制御に
  対応しているか未確認のため)
- 館内BGMのダッキングは別システム(ハード側)の自動処理に依存し、
  本システムからの明示的な音量制御コマンドは想定しない
  (要検証。7.1参照)

## 8. 未確定事項・要確認事項

- [ ] 館内BGMのダッキングは本当に完全自動(音声信号検知)か。
      それとも街時計/ステージ動画の再生と連動した何らかの
      制御信号が必要か
- [ ] ステージショー開始時、「イベント卓に切替済みか」を
      ZVが目視確認する運用のままでよいか、システム側に
      確認ステップ(チェックボタン等)を入れるか
- [ ] 音源・動画ファイルの命名規則、保存フォルダ構成
- [ ] 具体的なスケジュール一覧(何時に何を再生するか、
      館内BGMの種類は何パターンあるか)
- [ ] 再生中にPCがスリープ/スクリーンセーバーに入らないための
      電源設定の確認
- [ ] 音響映像システム(切替機材)の型番・API対応有無の確認
      (将来的な自動化余地の判断材料として)
- [ ] ステージ照明との連動について。現状は音響映像スタッフ側が組んだ
      システムで、ダンスショー等の再生と連動して照明(スライダー式の
      パターン卓)が自動で動く仕組みがあるとのこと。本アプリから連携
      できるかは、以下を現地で確認しないと判断できない:
      - 照明卓の型番
      - 卓にDMX(XLR3/5ピン)・USB・LAN(Art-Net)・MIDIなど外部入力
        端子があるか
      - 現状の「動画再生→照明が動く」は本当に信号連動か、AVスタッフが
        手動で同時操作しているだけか
      DMX等の外部入力があれば、USB-DMXインターフェースを追加すること
      で本アプリから照明パターン呼び出しができる可能性がある。
